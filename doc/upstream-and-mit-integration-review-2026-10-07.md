## Review and implementation rule

Each entry is handled individually: inspect the actual source/issue or PR diff; compare it with the current Apscribe implementation; reproduce any reported bug or demonstrate a missing workflow; verify code and asset licenses; choose a direct import, attributed adaptation, native implementation, or documented rejection; add a regression test; build and run the relevant suite; then commit the narrow slice. A priority is not a claim of reproduction or completion. Upstream Scribus PRs are GPL-family contributions to review, not MIT plugins.

## Integration completed in this slice

The native Find & Replace dialog now offers named, persistent *text-query* presets (find text, replacement text, regex, case, whole-word). This adapts the user-facing saved-query idea from Richard Sitányi's [GREPS](https://github.com/richard-cdbox/greps) (MIT; copyright 2025 richard-cdbox). No GREPS source code or Tkinter UI was copied. Matching and replacement remain in Apscribe's existing engine, to avoid the GREPS bulk-change path that calls Scripter `setText` and can discard text formatting (also related to [Scribus #110](https://github.com/scribusproject/scribus/issues/110)). The preset JSON is stored in user preferences, not in an SLA document; loading a preset never changes document content. Formatting criteria are not yet saved.

## Large-document zoom verification (8 October 2026)

`document_zoom_position` runs against the initialized native app, real document view, status-bar zoom control, and viewport wheel-event route using Qt's offscreen backend. It covers first/middle/last pages of 200-page documents, facing pages, first/middle/last pages of 1,000-page documents, repeated zoom-in/out commands, 25–150% field changes, requests for 3,200% and 32,000%, repeated requests beyond the safe limit, and Ctrl-wheel pointer anchoring both at ordinary zoom and at the limit. It also verifies that selected-object-centred zoom retains its existing behavior and selection, and that zooming does not mark the document modified. Pixel-rounding tolerances are scaled to the actual magnification. Test-only `--document-tests --suite=zoom` selects this suite without changing the earlier table regression.

The safety cap is derived from Qt's `QWIDGETSIZE_MAX`, the current canvas extents, and viewport headroom for pasteboard expansion. It applies to both axes and is not Mac-specific. It prevents the reproduced scroll-range truncation without changing ordinary magnification. **Limitation:** very long or wide documents cannot reach the nominal 32,000% maximum with the existing real-widget canvas. A virtual/tiled canvas is a separate design task if that range is required for these documents; this patch does not claim to implement one. The original MX Linux/XFCE report still needs its own reproducer and hands-on testing, as do Windows/Linux runtime checks.

Validation: the Mac build succeeds, the focused native regression passes, and all 57 CTest tests pass (74.38 seconds). `git diff --check` is clean. The build retains existing Homebrew-library deployment-target warnings; the native tests also report sandbox-denied font-cache/character-palette writes, as in the earlier inspector slice. No third-party implementation was copied; existing GPL notices are preserved.

## Pending-edit cleanup safety (8 October 2026)

The next native regressions reproduced a second cleanup problem: the usage scan reads applied document styles, while deletion reads the Style Manager's temporary copies. A used paragraph style renamed in the editor was therefore offered for deletion under its new name; an otherwise-unused parent newly selected in the editor was also offered for deletion. Accepting cleanup could delete these draft definitions and apply other pending edits as a side effect. The Scripter cleanup path instead deleted document styles and reloaded the manager, risking loss of the editor's drafts.

Cleanup now requires the user to **Apply or Reset** pending changes first. The Style Manager gives an actionable information message before scanning, deleting, switching modes, or applying anything. The Python `removeUnusedStyles()` entry point raises `RuntimeError` before modifying the document or refreshing the manager when pending changes exist; its integer return value and normal cleanup behavior are unchanged once the edits are resolved. Its help text documents this safety condition and the settings/dependency protection from the earlier slice. A shared `StyleManager::hasPendingChanges()` query includes invalid name drafts, without adding any data members or changing the document format.

The recovery check exposed a related editor bug: an initial blank or duplicate name disabled Apply/Done without enabling Reset, and Reset did not restore Done. Invalid names now leave Reset available; Reset restores Done, and entering a corrected valid new name restores Done even after a blank draft. This is not a general rewrite of name validation or style editing.

Eight additional data-driven native cases cover paragraph rename and parent changes with both explicit Apply and Reset, character renames through the actual Python console/plugin with both choices, and blank/duplicate name recovery. They verify that refused cleanup preserves the document's styles, text references, modified state, and editor drafts. After explicit resolution, cleanup removes the truly unused style while retaining the chosen name/dependency, and `.sla.gz` save/reopen preserves paragraph references, character references, and font size; a second cleanup is a no-op. The warning and confirmation cases drive real Qt widgets/dialogs with the offscreen backend; persistence runs in the normal isolated noninteractive test mode. No user documents were edited.

Modified code: `scribus/ui/stylemanager.{cpp,h}`, `scribus/plugins/scriptplugin/cmdstyle.{cpp,h}`, and `scribus/tests/testStyleCleanup.{cpp,h}`. Existing GPL/copyright notices and the mixed line endings of the Scripter files are preserved. No third-party code was imported. The UI and Python guards use platform-neutral Qt/C++ code.

## Document-setting style rename/replacement safety (8 October 2026)

The native review reproduced three problems. Typing a paragraph **or character** style name immediately changed the first matching entry in a legacy TOC source list; Reset did not undo that live-document mutation. Applying a rename or deleting with a replacement updated modern style-based TOC entries, but missed the attribute-based TOC text style and all five index styles. A separate character-editor bug left queued rename/deletion mappings intact after Reset/reload, so a later Apply could replay a canceled rename, remove the restored character definition, and change a note-mark reference—even in another document.

Style-name drafts no longer write TOC settings. The document's existing `replaceNamedResources()` commit path now remaps TOC text styles, both legacy source/output lists (including repeated names), modern TOC source/output entry styles, and index heading/separator/levels 1–3. An explicit "No Style" replacement clears the corresponding reference. Only paragraph-style mappings affect these fields; character styles with identical names remain a separate namespace. Note body/mark remapping already existed in this shared path and is preserved and tested. The character editor now discards queued mappings along with temporary definitions during reload, matching the paragraph editor's Reset behavior.

The new `style_settings_references` native CTest suite has nine data-driven cases: paragraph/character rename with Apply and Reset; used-style deletion with replacement, cancellation, and "No Style"; and character Reset followed by another Apply in the same or a new document. It clicks actual Style Manager controls and drives the real replacement dialog under Qt's offscreen backend. Checks include pending-draft isolation, modified state, namespace separation, unrelated TOC entries, non-style metadata with identical names, `.sla.gz` save/reopen, note-mark font size, TOC/index options, and preservation of referenced definitions during subsequent cleanup. Obsolete TOC lists are checked in memory only; the existing format does not serialize them. No user documents were edited.

There is no new document schema, public scripting API, application data member, or OS-specific implementation. Existing GPL/copyright notices are retained; no third-party code was imported.

## Default TOC page-number alignment (8 October 2026)

The [upstream #202 request](https://github.com/scribusproject/scribus/issues/202) asks for useful default TOC formatting without manually configuring tabs, while retaining manual adjustments. Apscribe now has **Align Page Numbers at Right Edge** in the common properties of each setup in **Document Setup → Tables of Contents**, also available in application preferences. Newly added setups enable it; existing documents/preferences without the new `AutoRightAlignPageNumbers` attribute load with it disabled. Existing setups can explicitly opt in.

Both style-based and attribute-based generators add a local right-aligned tab to entries whose page number is at the end and whose output paragraph has no custom tabs. The position uses the destination frame's column width, including frame insets, column gaps, and frame-stroke clearance, minus the paragraph right indent. Explicit or inherited custom tabs—including leaders—take precedence. Beginning/hidden numbers, chosen fonts, paragraph parents, and shared style definitions remain unchanged. Tabs are applied after all entries are written, preventing a generated tab from leaking into subsequent paragraphs with different settings. No third-party code was copied; existing GPL/copyright notices are retained.

The application-preference round-trip test independently reproduced another issue: saving a style-based TOC preset discarded its source and per-style entries, and wrote numeric page placement that the reader did not recognize. This same TOC persistence path now retains the source, ordered entries, output styles, line-break removal, placement and alignment option. It writes named placement values and still accepts legacy integers 0/1/2; absent/unrecognized placement safely defaults to End. SLA 1.7.0 and current-format writers/readers persist the alignment option, with absent attributes remaining false.

The initialized native `toc_default_alignment` suite exercises 22 cases under Qt's offscreen backend: both sources; automatic/off modes; inherited custom tabs/leaders; Beginning and Not Shown; no output style; repeated generation after real document-command resizing; inherited typography/indents and unchanged source text/shared styles; mixed entry settings; wrapped titles flowing through both columns; actual preference-pane add/toggle/cancel controls and serializer round trips; legacy numeric preferences; and save/reopen through the actual 1.7.0/current writers and readers, with and without the new attribute. It checks real laid-out page-number positions within the existing text engine's one-point legacy tab offset, not just stored tab values. Synthetic temporary files only; no user documents were changed.

Limitations: regenerate the TOC after changing frame size, insets, columns or paragraph indents—the option does not introduce live right-margin-relative tabs. It uses the destination frame's column width; linked destination frames with different column widths, shaped text areas/wrap obstructions, RTL and unusual paragraph alignments need separate fidelity review. The native pane regression is not a hands-on macOS GUI/light/dark review, and Windows/Linux runtime checks remain pending. No new public Scripter API or TOC undo workflow is claimed.
